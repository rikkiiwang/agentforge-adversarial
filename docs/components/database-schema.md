# Postgres schema

**Status:** Design-of-record, draft 2026-05-11. The 6 tables here are the
**single source of truth** for the platform. Referenced from
`ARCHITECTURE.md` §6 and `docs/agents/documentation-agent.md` §3.

---

## Conventions

- All IDs are `uuid` (generated by `uuid_generate_v4()` unless noted).
- All timestamps are `timestamptz` with UTC values.
- Enums use Postgres-native `CREATE TYPE` so they survive `pg_dump`.
- Foreign keys are declared `ON DELETE RESTRICT` everywhere; we never
  cascade-delete historical security data.
- Migrations: Alembic. Naming: `NNNN_<verb>_<table>_<noun>.py` (e.g.,
  `0003_add_pgvector_index_attack_runs.py`).
- All tables get `created_at` / `updated_at`; `updated_at` is maintained
  by a `BEFORE UPDATE` trigger (`set_updated_at`).

## 1. `attack_runs`

The canonical record of every attack execution. Written by the Judge
node when it emits a verdict. Heat-map, near-miss tile, and vuln board
queries all root here.

```sql
CREATE TYPE attack_source AS ENUM ('direct', 'random', 'mutator', 'regression');
CREATE TYPE judge_verdict AS ENUM ('pass', 'partial', 'fail');

CREATE TABLE attack_runs (
  id                   uuid        PRIMARY KEY DEFAULT uuid_generate_v4(),
  target_version       text        NOT NULL,                   -- git SHA from /healthz
  campaign_id          uuid        NOT NULL,                   -- groups runs in one Orchestrator dispatch
  category             text        NOT NULL,
  subcategory          text        NOT NULL,
  channel              text        NOT NULL,
  seed_id              text,                                   -- root seed (for lineage); null for first-ever
  parent_id            uuid        REFERENCES attack_runs(id), -- mutator chain; null for seeds
  source               attack_source NOT NULL,
  red_team_subagent_id text        NOT NULL,                   -- which swarm subagent generated it
  red_team_model       text        NOT NULL,                   -- e.g., "llama-3-70b-uncensored"
  attack_prompt        text        NOT NULL,                   -- the actual attack text
  transcript_uri       text,                                   -- pointer to full transcript in object store
  judge_verdict        judge_verdict NOT NULL,
  judge_reasoning      text        NOT NULL,
  judge_rubric_version text        NOT NULL,                   -- for drift detection
  category_validated   boolean     NOT NULL,                   -- did declared category match observed behavior
  cost_usd             numeric(10,4) NOT NULL,
  latency_ms           integer     NOT NULL,
  langfuse_trace_id    text,
  embedding            vector(384),                            -- pgvector; for novelty / dedup
  created_at           timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX attack_runs_target_version_idx ON attack_runs (target_version);
CREATE INDEX attack_runs_category_idx ON attack_runs (category, subcategory, channel);
CREATE INDEX attack_runs_campaign_idx ON attack_runs (campaign_id);
CREATE INDEX attack_runs_parent_idx ON attack_runs (parent_id);
CREATE INDEX attack_runs_verdict_idx ON attack_runs (judge_verdict);

-- pgvector HNSW for novelty filtering (synthesis stage 4)
CREATE INDEX attack_runs_embedding_hnsw_idx ON attack_runs
  USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);
```

## 2. `vulnerabilities`

Confirmed exploits in the state machine. Written by:
- **Documentation Agent** — initial INSERT with `state='discovered'`
- **Regression Harness** — UPDATE for `state='fix_validated'` / `'reopened'`
- **Humans (dashboard)** — UPDATE for `state='triaged'` / `'fix_proposed'` / `'closed'`

```sql
CREATE TYPE vuln_state AS ENUM (
  'discovered', 'triaged', 'fix_proposed',
  'fix_validated', 'closed', 'reopened'
);
CREATE TYPE vuln_severity AS ENUM ('low', 'medium', 'high', 'critical');

CREATE TABLE vulnerabilities (
  id                          uuid           PRIMARY KEY DEFAULT uuid_generate_v4(),
  originating_attack_run_id   uuid           NOT NULL REFERENCES attack_runs(id),
  parent_vuln_id              uuid           REFERENCES vulnerabilities(id),   -- class-probe variants
  state                       vuln_state     NOT NULL DEFAULT 'discovered',
  state_changed_at            timestamptz    NOT NULL DEFAULT now(),
  state_changed_by            text           NOT NULL,                          -- 'doc_agent' | 'regression_harness' | operator handle
  severity                    vuln_severity  NOT NULL,
  category                    text           NOT NULL,                          -- denormalized for heat-map speed
  subcategory                 text           NOT NULL,
  channel                     text           NOT NULL,
  threat_model_cell_id        uuid           NOT NULL REFERENCES threat_model_cells(id),
  target_version              text           NOT NULL,                          -- target_version at discovery
  first_seen_version          text           NOT NULL,
  last_seen_version           text           NOT NULL,
  assignee                    text,
  created_at                  timestamptz    NOT NULL DEFAULT now(),
  updated_at                  timestamptz    NOT NULL DEFAULT now(),

  -- Idempotency: one vuln per FAIL attack_run
  CONSTRAINT vuln_unique_originating UNIQUE (originating_attack_run_id)
);

CREATE INDEX vulnerabilities_state_idx ON vulnerabilities (state);
CREATE INDEX vulnerabilities_parent_idx ON vulnerabilities (parent_vuln_id);
CREATE INDEX vulnerabilities_category_idx ON vulnerabilities (category, subcategory);
CREATE INDEX vulnerabilities_severity_idx ON vulnerabilities (severity);
```

Note the `UNIQUE` constraint on `originating_attack_run_id` — this is
how the Documentation Agent's idempotency works. A retry of the same
FAIL signal cannot create a duplicate row; the agent does
`INSERT ... ON CONFLICT DO NOTHING RETURNING id`.

## 3. `vuln_reports`

One-to-one with `vulnerabilities`. Written and updated **exclusively**
by the Documentation Agent.

```sql
CREATE TYPE class_probe_status AS ENUM (
  'pending', 'in_progress', 'complete', 'not_applicable'
);

CREATE TABLE vuln_reports (
  vuln_id                       uuid           PRIMARY KEY REFERENCES vulnerabilities(id),

  -- Severity narrative
  severity_rationale            text           NOT NULL,        -- "baseline HIGH + modifier +1 (real PHI in output)"
  observed_behavior             text           NOT NULL,
  expected_behavior             text           NOT NULL,
  clinical_impact_narrative     text           NOT NULL,        -- why a CISO should care

  -- Reproduction
  repro_steps                   jsonb          NOT NULL,        -- { setup, attack_sequence, expected_failure }
  repro_attack_run_id           uuid           NOT NULL REFERENCES attack_runs(id),

  -- Suggested fix (defense-mapped + LLM narrative)
  suggested_fix                 text           NOT NULL,
  affected_defense_layer        text           NOT NULL,        -- e.g., "B5 PHI minimizer"
  defense_ref_path              text           NOT NULL,        -- file path or commit ref

  -- Class-probe boundary mapping
  class_probe_status            class_probe_status NOT NULL DEFAULT 'pending',
  class_probe_variant_count     integer,
  class_probe_affected_channels text[],

  -- Generation provenance
  generated_by                  text           NOT NULL,        -- "claude-sonnet-4-6@2026-05-11"
  generation_cost_usd           numeric(10,4)  NOT NULL,
  report_version                integer        NOT NULL DEFAULT 1,

  -- Human review
  human_reviewed_at             timestamptz,
  human_approved                boolean,
  human_reviewer_id             text,

  created_at                    timestamptz    NOT NULL DEFAULT now(),
  updated_at                    timestamptz    NOT NULL DEFAULT now()
);

CREATE INDEX vuln_reports_class_probe_status_idx ON vuln_reports (class_probe_status);
CREATE INDEX vuln_reports_review_idx ON vuln_reports (human_reviewed_at)
  WHERE human_reviewed_at IS NULL;  -- partial index for "pending review" queries
```

## 4. `near_misses`

One row per `PARTIAL` verdict. Tracks the variant-exploration lifecycle.
Written by the post-verdict routing logic (Orchestrator re-invocation);
read by the dashboard's Near-Miss tile.

```sql
CREATE TYPE near_miss_state AS ENUM (
  'exploring', 'escalated', 'exhausted', 'budget_capped'
);

CREATE TABLE near_misses (
  id                          uuid             PRIMARY KEY DEFAULT uuid_generate_v4(),
  originating_attack_run_id   uuid             NOT NULL REFERENCES attack_runs(id),
  state                       near_miss_state  NOT NULL DEFAULT 'exploring',
  escalated_to_vuln_id        uuid             REFERENCES vulnerabilities(id),  -- set when state='escalated'
  variant_count               integer          NOT NULL DEFAULT 0,
  rounds_used                 integer          NOT NULL DEFAULT 0,
  total_cost_usd              numeric(10,4)    NOT NULL DEFAULT 0,
  category                    text             NOT NULL,
  subcategory                 text             NOT NULL,
  channel                     text             NOT NULL,
  target_version              text             NOT NULL,
  created_at                  timestamptz      NOT NULL DEFAULT now(),
  updated_at                  timestamptz      NOT NULL DEFAULT now(),

  CONSTRAINT near_miss_unique_originating UNIQUE (originating_attack_run_id)
);

CREATE INDEX near_misses_state_idx ON near_misses (state);
CREATE INDEX near_misses_escalated_idx ON near_misses (escalated_to_vuln_id)
  WHERE escalated_to_vuln_id IS NOT NULL;
```

## 5. `regression_schedule`

Weekly replay queue. Written by the Regression Harness on FAIL fan-out
(insert) and on each weekly replay (update with new verdict).

```sql
CREATE TABLE regression_schedule (
  id                     uuid           PRIMARY KEY DEFAULT uuid_generate_v4(),
  attack_run_id          uuid           NOT NULL REFERENCES attack_runs(id),
  vuln_id                uuid           NOT NULL REFERENCES vulnerabilities(id),
  last_run_at            timestamptz,
  last_verdict           judge_verdict,
  last_target_version    text,
  target_versions_passed text[]         NOT NULL DEFAULT '{}',  -- versions where this attack replayed PASS
  rerun_interval_days    integer        NOT NULL DEFAULT 7,
  enabled                boolean        NOT NULL DEFAULT true,
  created_at             timestamptz    NOT NULL DEFAULT now(),
  updated_at             timestamptz    NOT NULL DEFAULT now()
);

CREATE INDEX regression_schedule_next_due_idx ON regression_schedule (last_run_at, enabled);
```

## 6. `threat_model_cells`

The structured taxonomy from `THREAT_MODEL.md`. The denominator of the
coverage heat-map. Versioned so coverage trends stay comparable across
taxonomy revisions.

```sql
CREATE TABLE threat_model_cells (
  id                    uuid         PRIMARY KEY DEFAULT uuid_generate_v4(),
  taxonomy_version      integer      NOT NULL,
  category              text         NOT NULL,
  subcategory           text         NOT NULL,
  channel               text         NOT NULL,
  quality_bars          jsonb        NOT NULL,        -- list of required dimensions
  impact                text         NOT NULL,
  severity_baseline     vuln_severity NOT NULL,
  defenses_referenced   jsonb        NOT NULL,        -- [ {id, name, location}, ... ]
  owasp_llm_id          text,                          -- e.g., "LLM01"
  atlas_id              text,                          -- e.g., "AML.T0051"
  created_at            timestamptz  NOT NULL DEFAULT now(),

  CONSTRAINT cell_unique_axis UNIQUE (taxonomy_version, category, subcategory, channel)
);

CREATE INDEX threat_model_cells_axis_idx ON threat_model_cells (category, subcategory, channel);
```

The `defenses_referenced` JSON shape mirrors what's declared in
`THREAT_MODEL.md`:

```json
[
  { "id": "B5", "name": "PHI minimizer",
    "location": "copilot/app/phi/minimizer.py" },
  { "id": "B4-L2", "name": "Layer-2 cross-patient rule",
    "location": "copilot/app/verification/rules.py" }
]
```

## Cross-table integrity

- A `vulnerabilities` row's `parent_vuln_id` must point to a vuln in the
  **same** category. Enforced by trigger (not FK alone).
- A `near_misses.escalated_to_vuln_id` may only be set when the row
  transitions to `state='escalated'`. Enforced by trigger.
- A `regression_schedule.vuln_id` must reference a vuln whose
  `originating_attack_run_id` matches the schedule's `attack_run_id`.
  Enforced by trigger.

Detail of trigger SQL goes into the first Alembic migration.

## Retention & backup

| Concern | MVP | Post-MVP |
|---|---|---|
| Backup cadence | Railway's daily logical backup | Continuous WAL archiving to S3 |
| Retention | Indefinite (all historical attack_runs kept) | Roll older `attack_runs` rows to cold storage; preserve embeddings + verdicts in summary table |
| PII / PHI in DB | None — transcripts go through the same PHI minimizer the Co-Pilot uses on output before insert | Add audit trail on transcript_uri reads |
| Embedding model swap | Manual re-embedding migration if model changes | Track embedding model version in a sidecar column (deferred) |
